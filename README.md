## 1.2.9 听书、书源与诊断

锁屏和亮屏时，朗读服务继续维护句段和进度。原章是试看或中段有缺失提示时，阅读会在已启用的本地书源里寻找可正常阅读的同书同章，用缺口前后的正文核对。

「我的 → 书源管理」的菜单内可清理待确认的失效规则，也能恢复已归档的书源。发现和订阅保留原分类，筛选、滚动和切换按当前显示的内容更新。

闪退后重开「阅读」，点「我的 → 上传使用日志」可取得回执。平时向 ChatGPT Dot 口述问题即可，由它提交并保留回执。[反馈入口](https://reading-feedback.iamnevillechen.workers.dev/) · [Dot 提交说明](https://reading-feedback.iamnevillechen.workers.dev/dot.json)

维护时也可以使用发布仓库的两项手动工作流。先从带 SHA-256 的源代码归档编译并运行单元测试，再在本机用原证书签署 APK。将签署后的应用和测试 APK 放进版本草稿，使用第二项工作流在 Android 15 上从旧版覆盖安装，并按类或方法运行原生测试。用 `tools/package.py --apk-dir` 打包同一个已测安装包，移除草稿里的临时构建和测试附件后发布。[编译工作流](tools/build-android-candidate.yml) · [覆盖升级与原生测试](tools/verify-android-release.yml)

在项目根目录生成工作流所用的归档，包含 Android 源码和手机、服务端共用的正文判定测试数据。

```sh
git -C upstream archive --format=tar.gz --output=../Reader-build-input.tar.gz \
  --prefix=server/shared/ --add-file=../server/shared/content-quality-v1.json \
  --prefix=upstream/ HEAD
```
